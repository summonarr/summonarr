# Guardrail 40c

_The id is a permanent address; CLAUDE.md keeps the headline and hard rules._

40c. **"For You" is built from the VIEWER'S OWN records. Cross-viewer co-watching is opt-in, default OFF. Nothing here is ever a play.**

## What feeds a viewer's shelf

| Signal | Table | Imported by | Effect |
|---|---|---|---|
| Live watch log (since install) | `PlayHistory` | the 5s poller / SSE (guardrail 19) | history seeds, "already watched" |
| The media servers' own history (back past the install) | `ServerWatchedTitle` (`plays > 0`) | `importServerWatchHistory`, phase 0 of warm-recommendations | history seeds, "already watched" |
| Jellyfin favorites (the heart) | `ServerWatchedTitle.favorite` | same | loved (×1.75), "already known" |
| Trakt history | `TraktWatchedItem` | `syncTraktUsers` | history seeds, "already watched" |
| Trakt ratings (1–10) | `TraktRating` | `syncTraktUsers`, same switch and stamp as the history | 8–10 loved, 5 lukewarm, ≤ 4 never a seed; "already known" |
| Summonarr watchlist / requests | `WatchlistItem` / `MediaRequest` | the app | seeds (unchanged) |
| Episodes the server holds | `TVEpisodeCache` | library sync | quit-show judgement |
| Co-watching (OPT-IN) | `CoWatchSuggestion` | `refreshCoWatchEdges` in the graph build | extra candidates under the viewer's own seed |

All of it is local by the time seeds are selected, so the per-viewer pass still makes no upstream call (guardrail 40).

## Why

- `PlayHistory` is the live poller's log and starts the day Summonarr was installed. Plex keeps every account's history and Jellyfin every user's played flags, going back years. Without them, For You seeded from a sliver of someone's taste and recommended titles they had watched before the install.
- Watching is not liking. A title rated 3/10 produced "Because you watched X", and two episodes of a sixty-episode series counted as a modest "liked it".
- Different viewers on one server must not leak to each other. Co-watching is useful on a busy server and a privacy question on a household one, so it is the admin's choice and starts off.

## Import rules (`server-watch-history.ts`, `server-watch-history-data.ts`)

- **Whose history.** Co-watch OFF (default): only identities linked to a Summonarr account are read and stored — a shelf is its own viewer's, and an unlinked Jellyfin identity would otherwise cost a request every run. Co-watch ON: every active identity, because co-watching is built from everyone's viewing. Favorites are read for linked identities only, either way.
- **Incremental, per identity.** `ServerWatchCursor.readTo` is the newest play already counted, per `MediaServerUser`. Plex is walked once per server (`/status/sessions/history/all`, newest first) back only to the OLDEST eligible identity's read point; an identity never read forces one full walk (capped at `PLEX_HISTORY_IMPORT_MAX`, newest kept, warned once). Each Jellyfin user is asked for what they played since their read point (one request when nothing changed), and a linked identity for its favorites (one request).
- **Counted once.** A play counts strictly AFTER the read point, never at it. An identity's rows and its read point commit in ONE transaction: a failed write leaves both, so the next run re-reads the same window and counts it once. An identity with nothing new is not rewritten.
- **Jellyfin counts.** A full read takes each item's `PlayCount` (the lifetime tally). An incremental read adds ONE per item played since the read point. Adding `PlayCount` again would recount every earlier play of a rewatched item.
- **Plex owner.** The owner's plays are recorded under the local account id `"1"`, rewritten to the owner's plex.tv id. When plex.tv cannot say who the owner is, the owner's read point HOLDS (watch sync's rule, 19e).
- **Abort.** A walk cut short writes nothing and moves no read point (guardrail 41).
- **Mapping.** Through the library cache only: Plex by ratingKey over both key columns (37c, one owner per key — 37b), Jellyfin by item id over both id columns (37), lowest tmdbId on a shared id. An item not in the library is counted as `unresolved` and skipped.
- **Never a play.** Nothing writes `PlayHistory`, and no stat, activity page or play count reads `ServerWatchedTitle`.
- **Lifecycle.** FK `MediaServerUser` with `onDelete: Restrict` (28). De-registering an instance deletes its identities' rows and read points in the registry's transaction (35). A purge unlinks the identity, so the rows stay unattributed like `PlayHistory`. Backed up (servers prune old history, so it can't always be rebuilt).

## Taste and quit-show rules (`recommendations.ts`)

- `tasteFactor(rating, favorite)`: a rating outranks a favorite. ≤ 4 → 0 (never a seed, dropped BEFORE the history merge so the next watch takes the slot); 5 → `TASTE_MEH_FACTOR`; 6–7 → 1; 8–10 or a favorite → `TASTE_LOVED_FACTOR`.
- A dislike removes only its own seed. It is never fanned out to titles that resemble it: the 2026-08 audit rejected anti-seed neighbourhoods (hides concentrate in the densest taste region, so a few can invert a shelf), and ratings have the same flaw.
- **Loved pool.** A loved title the recency-ordered pools did not reach seeds from its own pool (`MAX_LOVED_SEEDS`, newest evidence first, only titles known to be watched). It is a seed cap, so it is a build-budget knob: the per-user ceiling is now 300 + 24 + 24 + 24 = **372** (guardrail 40).
- **Wire labels.** Every seed keeps one of `WATCH_HISTORY`/`WATCHLIST`/`REQUEST`; a loved-pool seed is `WATCH_HISTORY`. Never add a `RecommendationSeed` value for these: the iOS app decodes the enum.
- **Quit shows.** A series seed is damped by `QUIT_SHOW_DAMP` when it has at most `QUIT_SHOW_MAX_PLAYS` episode plays, under `QUIT_SHOW_MAX_RATIO` of the regular-season episodes the server holds (season 0 excluded; the larger of the Plex and Jellyfin counts), the server holds at least `QUIT_SHOW_MIN_EPISODES`, the last watch is `QUIT_SHOW_SETTLE_MS` old, and it is not loved. A series not on the server is never judged.

## Co-watching (`recommendation-graph.ts`) — OPT-IN

- Behind `feature.behavior.forYouCoWatch`, **default OFF**. Off: the per-viewer pass reads no edge, the build runs no cross-viewer query, and it DELETES any edges an earlier "on" left. On: the build rebuilds `CoWatchSuggestion` whole each run from `PlayHistory` (watched) ∪ `ServerWatchedTitle` (`plays > 0`), in ONE aggregate inside Postgres under a transaction-scoped 60s `statement_timeout`; on failure the previous edges stay.
- **Privacy floors.** A person is a Summonarr account (all its identities count once) or an unlinked identity. An edge X → Y needs at least `COWATCH_MIN_VIEWERS` (3) people who watched both, at least `COWATCH_MIN_NON_VIEWERS` (2) people with history who did not (the viewer it is shown to is always one, so at least one other is too — no edge can say "everyone else watched this"), and at least `COWATCH_MIN_PEOPLE` (5) people with history on the server. Favorites with no plays and unfinished plays never count.
- **Indistinguishable.** A co-watch pick wears the viewer's own "Because you watched X" line, so a viewer cannot tell which picks came from co-watching.
- **Never coverage.** Co-watch votes are outside `coveredSeeds` and `rawSuggestions`: `conclusive` stays a TMDB question, so co-watching can never make a shelf built during a TMDB outage look complete.
- Display fields come from LOCAL caches only (the TMDB details blob, else `TmdbMediaCore`); the build makes no TMDB call. Targets are registered as graph nodes so the ratings pass gives them verdicts, and share the priority budget with TMDB targets. `DELETE /api/admin/clear-cache?source=tmdb` deletes the edges too.
- Scored by cosine similarity, so a title everyone watched does not top every list. Weighted below a TMDB suggestion at the same position (`COWATCH_WEIGHT`).

## Verification

- `tests/server-watch-history.test.mts`: folding rules, the run's incremental/idempotent/atomic behaviour, owner hold, abort, favorites only for linked identities, no `PlayHistory` write.
- `tests/recommendations.test.mts` (the `40c` block): pre-install seeds and exclusion (compute and read time), dislike veto and its switch, loved boost, loved pool and its wire label, quit-show damp and its three exemptions, co-watch off by default (no read, no query, edges cleared), co-watch on, co-watch outside coverage.
- `tests/trakt-user.test.mts`: ratings import, the stamp including `rated_at`, deletion with the history.
- Mutation-verified: 20 of 21 mutations fail a named test. The survivor removes the post-walk abort check, which the per-identity loop's own abort check makes redundant.
- The co-watch SQL was run against a throwaway Postgres 17 with fixtures for every floor: a 2-viewer pair, a pair watched by all but one person, a 4-person server, an account with two identities, 0-play favorites and unwatched plays. Each behaved as specified.
