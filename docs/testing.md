New tests colocate in `tests/*.test.mts` and import source with an explicit `.ts` extension (`allowImportingTsExtensions` is enabled). The runner registers [tests/_loader.mjs](../tests/_loader.mjs) via `--import` (see the npm script): it resolves the `@/*` alias, extensionless relative imports, a `server-only`/`client-only` stub, and rewrites `next/server|headers|navigation` to their real `.js` files — so nearly all of `src/lib` *loads* in tests (only `.tsx`-importing modules like `nav-items.ts` don't). Two constraints remain: source must use **erasable TS syntax only** (no constructor parameter properties — Node strip-only mode rejects them; `backup-crypto.ts`, `arr.ts`, `play-history.ts` were desugared for this), and tests must never hit a real DB or the network (stub `prisma` models in-memory — see `tests/jellyfin-config.test.mts` / `tests/poster-cache.test.mts` for the two established patterns — and mock `globalThis.fetch`/sockets). CI also runs a headless E2E route crawl ([.github/workflows/e2e.yml](../.github/workflows/e2e.yml) → [scripts/e2e-crawl.mts](../scripts/e2e-crawl.mts)): it builds the app against a throwaway Postgres, seeds an admin via [scripts/e2e-seed.mts](../scripts/e2e-seed.mts), signs in, and fails on any uncaught client error (React #418 hydration mismatches in particular — guardrail 16). It cannot run locally without the full stack; it has no Plex/Jellyfin/ARR/TMDB backends, so it gates hydration/runtime correctness only, not data-dependent behaviour.

## Real-Postgres suite (`npm run test:db`)

The unit suite above stubs Prisma, so it cannot see transaction rollback, `UPDATE … RETURNING` races, advisory locks or raw SQL. `tests/db/*.test.mts` runs the app's own `@/lib/prisma` client against a real Postgres 17 and is NOT part of `npm test`.

- `npm run test:db` starts a throwaway `postgres:17-alpine` container (needs Docker), runs `prisma db push`, runs the files one at a time, and removes the container. `TEST_DATABASE_URL=… npm run test:db` uses an existing disposable database instead.
- The tests TRUNCATE tables. `tests/db/_harness.mts` refuses any database whose name does not contain `test` or `ci`.
- Covered today: the "now available" claim CAS (all three paths), the staged library swap (instance scoping, lock 2001,1, array columns), `Setting` encryption at rest, a swallowed error inside `$transaction` (guardrail 23), `withAdvisoryLock` exclusivity and release, `withAdvisoryLock` aborting its work when its connection is terminated (guardrail 41), quota/library-row scoping evaluated by Postgres (`tests/db/scoping-and-lock-loss.test.mts`), and the episode cache's unchanged-set skip — the JS and SQL digests agreeing on multi-byte text, separators, nulls vs empty strings and millisecond timestamps, and an out-of-band edit read as a change (`tests/db/episode-cache-digest.test.mts`), the personal watch history's SQL grouping against its Prisma entry detail, its whole-group search (`tests/db/my-watch-history-parity.test.mts`), the statistics time zone's buckets and day bounds (`tests/db/stats-time-zone.test.mts`), the play-history raw SQL — activity calendar, heatmap drill-down, `TRANSCODE_REASON_SQL` and the Statistics fan-out (`tests/db/play-history-sql.test.mts`), the `/admin/stats` aggregates (`tests/db/admin-stats-requests.test.mts`, `tests/db/admin-stats-users-library-issues.test.mts`), notification retention (`tests/db/notification-retention.test.mts`), `patchPlexShowFilePaths` (`tests/db/patch-plex-show-file-paths.test.mts`), the play-history finalize that extends an early record of the same sitting, the batched retention purge and `/popular`'s single ranking statement (`tests/db/play-history-record-popular.test.mts`), and `withAdvisoryLock` holding a timed-out run's lock until its work returns (`tests/db/transactions-and-locks.test.mts`, guardrail 41). Unit stubs that must honour a `where` use `memoryTable` from `tests/_where.mts` (a stub written as `findMany: async () => rows` ignores every filter, so dropping one leaves the test green).
- Mutation-checked: each of dropping the status predicate, dropping the `notifiedAvailable` predicate on the fallback path, unscoping the swap delete, and removing the swap lock fails a named test. The `notifiedAvailable` predicate on the `markAvailable` path is redundant with the status predicate by design, so it has no killing test.
- Runs in CI as the `db-tests` job in `.github/workflows/ci.yml` (Postgres service container + `TEST_DATABASE_URL`).
