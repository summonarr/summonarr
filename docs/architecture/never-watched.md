# Never watched

_Moved verbatim from CLAUDE.md "Core architecture"._

**Never watched** — [never-watched.ts](../../src/lib/never-watched.ts) (pure verdict) + [never-watched-data.ts](../../src/lib/never-watched-data.ts) (evidence loader) + [never-watched-report.ts](../../src/lib/never-watched-report.ts) (report, cache, chip read) + [upstream-watch.ts](../../src/lib/upstream-watch.ts)/[upstream-watch-data.ts](../../src/lib/upstream-watch-data.ts) (the media servers' own watch records), page `/admin/never-watched` behind `feature.admin.neverWatched` (default ON), ADMIN-only, read-only.
- Every library title — and every season of a show that HAS been watched — with no play in the server's recorded history, biggest first, server-paged (`GET /api/admin/never-watched`). Guardrail 14d has the verdict rules.
- Deleting from the page goes through Library cleanup's dry run → confirm (the shared [cleanup-delete.tsx](../../src/components/admin/cleanup-delete.tsx) flow); "eligible" is exactly that dry run's selection. With cleanup off the page is a report.
- The upstream snapshot (`UpstreamWatchEvidence`) is refreshed daily by `/api/cron/refresh-upstream-watch` (lock 2041, `UPSTREAM_WATCH_SYNC_INTERVAL`) and on demand (`POST /api/admin/never-watched/refresh` — the page runs it as a BACKGROUND job: `async: true` → 202 `{ job }`, poll `GET ?job=` on the same route, the 37a pattern through `startArrJob`/`jobResponse`; the same admin re-asking while theirs runs joins it with no rate token; the synchronous default stays for API callers).
- Each server may spend what is left of a 25-minute run budget (`UPSTREAM_RUN_BUDGET_MS`, below the lock's 30-minute timeout) minus a reserve held for each server after it (`UPSTREAM_SERVER_RESERVE_MS`, 3 min, scaled down by `upstreamServerReserve` so the first server always gets at least half) — never an even split, which capped the first server (always Plex) at a fraction of the run; one that runs out is recorded failed (`timed out`) and keeps its previous snapshot, and the run moves on — one slow server never blocks the others or turns the daily job into a 5-minute retry loop.
- An ADMIN-only chip on the movie/TV detail pages and a line on `/admin/stats` read the same verdict. The chip reads the Radarr/Sonarr index only when the shared one is already in memory (`peekCachedArrLibraryIndex` — a page render never lists an arr), so on a cold cache it can count a delivery the report drops (a title its instance re-added since) and show an EARLIER "since" date until the index is warm.
