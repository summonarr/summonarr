# Request "Why?" status

_Moved verbatim from CLAUDE.md "Core architecture"._

**Request "Why?" status** — `GET /api/requests/[id]/arr-status` (MANAGE_REQUESTS), opened by the "Why?" button on APPROVED rows of the request queue ([request-arr-status.tsx](../../src/components/admin/request-arr-status.tsx), read on click only). One verdict plus details from the request's OWN instance (tmdbId, mediaType, arrInstance — guardrail 32; a Sonarr series is found by tmdb id, else by the request's stored tvdbId — Sonarr-sourced, the push and the webhook write it, so no TMDB-agreement check — the `requestIdentity` rule): the title, its `/api/v3/queue/details`, its DownloadFailed history since `approvedAt ?? createdAt` (counted per DOWNLOAD — Sonarr writes one record per episode of a pack, so records sharing a `downloadId` within 1 h are one failure; a failure an import of the title came at or after is answered, and the title then reads incomplete or waiting), read beside its import history, and whether a library the REQUESTER can see holds it (guardrail 35). The precedence and its reasons are in the header of [request-arr-status.ts](../../src/lib/request-arr-status.ts) (pure); reads in [request-arr-status-data.ts](../../src/lib/request-arr-status-data.ts).
- `ready` mirrors the library marking pass; "the arr has it, no library" mirrors the ARR marking pass, which skips a requester with a media-server preference (`User.mediaServer`) — that request waits for a library (`waitingForLibrary`), not the next sync. Completeness is `sonarrSeriesCompletion` (14a), the release rule is the Missing page's `missingMovie`.
- A monitored Sonarr series with no aired monitored episode, none on disk and no monitored airing ahead reads `unmonitored` (`monitored` stays true; Re-push is not offered — it re-monitors only an unmonitored series).
- A failed read is the `unreachable` verdict, never a 500. The next action calls the row's own Search / Pick release / Re-push; a TV Search (`PATCH /api/requests/[id]` `{ search: true }`) queues the Missing plan on the request's own instance (`findSeriesIdOnInstance` + `searchMissing` — `planSeriesSearch`, never SeriesSearch), and a series with nothing missing answers a translated `arrError`, never an upgrade search. A download needing attention links the queue filtered to the title for ADMIN only (`canOpenQueue` + the additive `queue` filter — the arr's row id leaves the route only with an admin; a delegate's answer carries neither). Delegates read it, so guardrail 5g.
