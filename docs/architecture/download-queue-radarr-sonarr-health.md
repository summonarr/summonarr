# Download Queue + Radarr/Sonarr health

_Moved verbatim from CLAUDE.md "Core architecture"._

**Download Queue + Radarr/Sonarr health** — page `/admin/queue`, ADMIN-only. [arr-queue.ts](../../src/lib/arr-queue.ts) (pure) + [arr-queue-data.ts](../../src/lib/arr-queue-data.ts); [arr-health.ts](../../src/lib/arr-health.ts) (pure) + [arr-health-data.ts](../../src/lib/arr-health-data.ts).
- The queue is a live paged `/api/v3/queue` read per configured instance of both services (unknown/unmatched items included — they are the ones that need an admin), one row per DOWNLOAD: Sonarr's per-episode records fold on `downloadId`. "Needs attention" is Radarr/Sonarr's own verdict (tracked status warning/error, import blocked/failed, client failed/unavailable) — nothing here guesses from progress or age.
- Row actions mirror Radarr/Sonarr's own queue screen. **Import** (import-blocked/pending rows) is the arr's Manual Import: `GET/POST /api/admin/queue/import`, with per-file corrections — re-match the movie, or the series + season + episodes (`import/targets`, `import/episodes`), the quality, languages, release group and Sonarr release type — each re-judged live by the arr's own reprocess before importing (`import/preview`; `rechecked: false` on an arr without it). Guardrail 5d. **Blocklist & search**, **Blocklist** and **Remove** open one confirm dialog with the arr's two choices: blocklist (and search / only / don't) and removal method (remove from client / change category — only when the client has a post-import category / ignore). Guardrail 5c. A release the arr is HOLDING (delay profile, client unavailable, fallback — `QueueItem.pending`) gets **Grab now** (`POST /api/admin/queue/grab`, the arr's `queue/grab/bulk`) instead of blocklist-and-search, and its removal has no method (nothing is in a client yet).
- Each row carries everything the arr's own queue shows — quality + revision tag, languages, custom formats + score, size/left, progress, time left/ETA, added, protocol, download client, indexer, output path, download id. The table's columns are picked per browser (localStorage, defaults otherwise) and every row expands to a details panel with all of it. The output path is a filesystem path, which is fine only because the page and `GET /api/admin/queue` are ADMIN-only.
- **Re-check downloads** (`POST /api/admin/queue/recheck`) queues `RefreshMonitoredDownloads` on every enabled instance — the retry for a blocked import after fixing its cause outside Summonarr. Not audited, rate-limited.
- The health panel (also in Settings → Webhooks, webhook part only) shows each instance's version, its own `/api/v3/health` checks, and whether its Connect list holds a working Summonarr webhook (`evaluateWebhook`: current token AND every handled event the version supports). **Set up / Repair webhook** writes that Connect entry for the admin — guardrail 2a. Radarr/Sonarr `Health`/`HealthRestored` webhook deliveries are forwarded to the outbound channels as `arr.health`/`arr.health_restored` (guardrail 14c), still acknowledged BEFORE the replay digest. The forwarder holds back only a REPEAT of the same state for the same check within 10 minutes; a change of state (failing → restored → failing) is always sent, or the admin's last word could be "restored" while the check is down ([arr-health-notify.ts](../../src/lib/arr-health-notify.ts)). The polled queue read passes `arrFetch(..., { quietErrors: true })` and logs a down instance once through `warnOnChange` (guardrail 7b).
